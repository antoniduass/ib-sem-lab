# ib-sem-lab

Учебное веб-приложение по информационной безопасности — «защищённый блокнот».
Пользователь входит в систему в три шага, пишет сообщение, шифрует его RSA-32768
или Кузнечиком, подписывает своей ЭЦП по ГОСТ и скачивает в PDF с подписью.

Вся криптография написана вручную, без готовых криптобиблиотек, и проверена
контрольными примерами из стандартов. Требования — [`assignment/SPEC.md`](assignment/SPEC.md).

## Установка

```bash
uv sync
cp .env.example .env
```

### База данных

Проект использует собственный кластер PostgreSQL в `instance/pgdata` (порт 5433,
только localhost, без пароля) — так он не зависит от других установок PostgreSQL:

```bash
initdb -D instance/pgdata -U ib --auth-local=trust --auth-host=trust -E UTF8 --locale=C
pg_ctl -D instance/pgdata -o "-p 5433 -c listen_addresses=localhost" -l instance/postgres.log start
createdb -h localhost -p 5433 -U ib ib
createdb -h localhost -p 5433 -U ib ib_test
set -a; source .env; set +a
uv run flask --app app init-db
```

### Почта

Письма (коды входа) уходят на локальный SMTP-сервер Mailpit — внешние почтовые
сервисы не используются:

```bash
brew install mailpit
mailpit --listen 127.0.0.1:8025 --smtp 127.0.0.1:1025 > instance/mailpit.log 2>&1 &
```

Почтовый ящик со всеми письмами — http://127.0.0.1:8025.

Остановить кластер: `pg_ctl -D instance/pgdata stop`. База `ib_test` нужна тестам
(адрес — `TEST_DATABASE_URL`), тесты очищают её таблицы.

## Запуск

```bash
set -a; source .env; set +a
uv run flask --app app run
```

Проверка: `http://127.0.0.1:5000/health` возвращает `{"status": "ok"}`.
Страницы: `/register` — регистрация, `/login` — вход, `/reset` — сброс пароля,
`/messages` — сообщения, `/verify` — проверка подписи PDF (доступна и гостю),
`/account` — кабинет, `/admin` — администрирование (только администратор).

Роли: гость, пользователь (назначается при регистрации), администратор.
Первого администратора назначает команда:

```bash
uv run flask --app app set-role <логин> admin
```

Вход — в три шага, каждый следующий доступен только после предыдущего:

1. логин и пароль (PBKDF2 на Стрибоге);
2. 6-значный код из письма: действует 10 минут, срабатывает один раз, в базе хранится
   только его хэш Стрибогом;
3. файл закрытого ключа ЭЦП, который пользователь скачивает при регистрации: сервер
   подписывает им случайную строку по ГОСТ 34.10 и проверяет подпись открытым ключом
   из базы. Закрытый ключ на сервере не хранится.

После 5 неудачных попыток на шаге 2 или 3 вход начинается заново.

Коды восстановления: при регистрации пользователь получает 10 одноразовых кодов
(показываются один раз, в базе — только хэши Стрибогом). Код восстановления заменяет
при входе один из шагов — код из письма или файл ключа (не больше одного за вход),
а при сбросе пароля — код из письма. В кабинете видно, сколько кодов осталось;
там же можно выпустить новый набор кодов и новый файл ключа ЭЦП.

Сброс пароля: email → код из письма (10 минут, один раз) или код восстановления →
новый пароль с теми же требованиями. Страница не сообщает, зарегистрирован ли email.
После смены пароля все открытые сессии пользователя закрываются.

Сообщения: пользователь выбирает шифрование — RSA-32768 (ключ системы) или Кузнечик
в режиме гаммирования (для каждого сообщения новый случайный ключ, он хранится
зашифрованным мастер-ключом сервера). Зашифрованное сообщение вместе с автором,
временем и алгоритмом подписывается ЭЦП автора по ГОСТ 34.10. Каждое сообщение можно
расшифровать (RSA — около 30 секунд) и скачать в PDF: внутри шифртекст, подпись
и ключ проверки. Страница `/verify` проверяет подпись загруженного PDF.

Секреты сервера лежат в `instance/` и не попадают в Git: `master_key.bin` (создаётся
автоматически при первом использовании) и ключ RSA `rsa_private_key.json`
(см. «Ключ RSA-32768»). Без ключа RSA работают все функции, кроме RSA-сообщений.

Сессии хранятся на сервере, в PostgreSQL: в cookie — только случайный токен
(HttpOnly, SameSite=Lax), в базе — его хэш Стрибогом-512; при входе токен меняется,
сессия живёт час с последнего запроса. Все формы защищены CSRF-токеном.
Роль проверяется на сервере для каждой закрытой страницы.

Пароль хранится как PBKDF2-HMAC-Стрибог-512 (RFC 9337): случайная соль 16 байт,
1000 итераций, хэш 64 байта. Регистрация занимает около 1,3 с — это цена итераций
на самописном Стрибоге.

## Ключ RSA-32768

Ключ системы создаётся один раз и хранится в `instance/` (не попадает в Git):

```bash
uv run python -m gostcrypto.rsa instance/rsa_private_key.json
```

На 8 ядрах (Apple Silicon) генерация заняла 19 минут. Простые числа ищутся параллельно
на всех ядрах, кандидаты заранее отсеиваются делением на простые до миллиона.
Шифрование — доли секунды, расшифрование одного блока (до 4085 байт) — около 30 секунд.

Для демонстрации подойдёт ключ на 2048 бит — он создаётся за доли секунды:

```bash
uv run python -m gostcrypto.rsa instance/rsa_demo_2048.json 2048
```
