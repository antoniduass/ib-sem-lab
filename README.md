# ib-sem-lab — «Защищённый блокнот»

Семестровый проект по информационной безопасности: веб-приложение, в котором
пользователь входит в систему в три шага, пишет сообщение, шифрует его RSA-32768
или Кузнечиком, подписывает своей ЭЦП по ГОСТ и скачивает в PDF с подписью.

Вся криптография написана вручную, без готовых криптобиблиотек, и проверена
автоматическими тестами на контрольных примерах из стандартов.
Требования — [`assignment/SPEC.md`](assignment/SPEC.md).

## Лабораторные работы

| № | Лаба | Где в проекте | Чем проверено |
|---|---|---|---|
| 1 | RSA-32768 | `gostcrypto/rsa.py`, `gostcrypto/modular.py`, `gostcrypto/primes.py`; шифрование сообщений | учебный пример, совместимость с OpenSSL в обе стороны, рабочий ключ 32768 бит |
| 2 | Кузнечик (ГОСТ 34.12-2018) и режим гаммирования (ГОСТ 34.13-2018) | `gostcrypto/kuznyechik.py`, `gostcrypto/ctr.py`; шифрование сообщений и ключей | все контрольные примеры ГОСТ 34.12 (А.2) и ГОСТ 34.13 (А.2.3) |
| 3 | Стрибог-512 (ГОСТ 34.11-2018) | `gostcrypto/streebog.py`, `gostcrypto/kdf.py`; хэш паролей, кодов, сессий | примеры ГОСТа с промежуточными значениями; HMAC и PBKDF2 — примеры RFC 7836 и RFC 9337 |
| 4 | ЭЦП (ГОСТ 34.10-2018) | `gostcrypto/gost3410.py`; третий фактор входа, подпись сообщений, PDF | оба примера ГОСТа (256 и 512 бит) с промежуточными значениями, ключи RFC 7836 |
| 5 | Трёхфакторная аутентификация | `app/auth.py`: пароль → код из письма → файл ключа ЭЦП | `tests/test_three_factor.py` |
| 6 | Регистрация с регулярными выражениями | `app/validation.py` (одни выражения для сервера и браузера), `app/auth.py` | `tests/test_validation.py`, `tests/test_register.py` |
| 7 | Восстановление пароля | `app/reset.py` | `tests/test_reset.py` |
| 8 | Одноразовые коды и коды восстановления | `app/codes.py`, `app/recovery.py` | `tests/test_three_factor.py`, `tests/test_recovery.py` |
| 9 | Почтовый сервер на localhost | Mailpit, `app/mail.py` | живая проверка: письмо с кодом в локальном ящике |

Дополнительно: три роли (гость, пользователь, администратор) с проверкой на сервере,
администрирование и журнал входов, страница `/demo`, где RSA, Кузнечик и Стрибог
работают по отдельности на контрольных примерах стандартов.

## Установка с нуля

Нужны macOS или Linux, [uv](https://docs.astral.sh/uv/) (он сам поставит Python 3.13),
PostgreSQL 14 или новее и [Mailpit](https://mailpit.axllent.org/). На macOS:

```bash
brew install uv postgresql@14 mailpit
```

Все команды ниже выполняются из корня проекта.

**1. Зависимости и настройки**

```bash
uv sync
cp .env.example .env
```

**2. База данных.** У проекта собственный кластер PostgreSQL в `instance/pgdata`:
порт 5433, только localhost, без пароля. Другие установки PostgreSQL он не трогает.

```bash
initdb -D instance/pgdata -U ib --auth-local=trust --auth-host=trust -E UTF8 --locale=C
pg_ctl -D instance/pgdata -o "-p 5433 -c listen_addresses=localhost" -l instance/postgres.log start
createdb -h localhost -p 5433 -U ib ib
createdb -h localhost -p 5433 -U ib ib_test
set -a; source .env; set +a
uv run flask --app app init-db
```

**3. Почта.** Письма с кодами уходят на локальный SMTP-сервер Mailpit,
внешние почтовые сервисы не используются:

```bash
mailpit --listen 127.0.0.1:8025 --smtp 127.0.0.1:1025 > instance/mailpit.log 2>&1 &
```

Ящик со всеми письмами — http://127.0.0.1:8025.

**4. Ключ RSA-32768.** Создаётся один раз и хранится в `instance/`:

```bash
uv run python -m gostcrypto.rsa instance/rsa_private_key.json
```

Генерация долгая: на 8 ядрах Apple Silicon — 19 минут (простые числа по 16384 бита
ищутся параллельно на всех ядрах). Без этого ключа работает всё, кроме RSA-сообщений.

**5. Запуск**

```bash
set -a; source .env; set +a
uv run flask --app app run
```

Приложение — http://127.0.0.1:5000. Первого администратора назначает команда
(после регистрации пользователя):

```bash
uv run flask --app app set-role <логин> admin
```

**После перезагрузки компьютера** база и Mailpit не запускаются сами — нужно повторить
команды `pg_ctl ... start` (шаг 2) и `mailpit ...` (шаг 3). Остановить базу:
`pg_ctl -D instance/pgdata stop`.

## Сценарий показа

1. **Регистрация** (`/register`): неверные поля подсвечиваются ещё в браузере, сервер
   проверяет их повторно. После регистрации — файл ключа ЭЦП и 10 кодов восстановления.
2. **Вход** (`/login`): пароль → код из письма в Mailpit (http://127.0.0.1:8025) →
   загрузка файла ключа. Без любого шага кабинет не откроется.
3. **Сообщения** (`/messages`): создать сообщение Кузнечиком и RSA, расшифровать
   (RSA — около 30 секунд), скачать PDF с подписью.
4. **Проверка подписи** (`/verify`, можно без входа): загрузить PDF — «Подпись верна».
   Испорченный файл — «Подпись неверна».
5. **Восстановление** (`/reset`): код из письма или код восстановления → новый пароль.
6. **Администрирование** (`/admin`): сменить роль, заблокировать пользователя (его открытая
   сессия сразу закрывается), посмотреть журнал входов (`/admin/log`).
7. **Шифры по отдельности** (`/demo`): поля уже заполнены контрольными примерами
   ГОСТ 34.11 и ГОСТ 34.13 — результат совпадает со стандартом. Для RSA есть быстрый
   демонстрационный ключ на 2048 бит.

## Как устроена защита

- **Пароли** — PBKDF2-HMAC-Стрибог-512 (RFC 9337): случайная соль 16 байт, 1000 итераций.
  Открытый пароль нигде не хранится.
- **Вход в три фактора**: пароль; 6-значный код из письма (10 минут, один раз, в базе только
  хэш); файл закрытого ключа ЭЦП — сервер подписывает им случайную строку и проверяет
  подпись открытым ключом из базы. После 5 ошибок на шаге 2 или 3 вход начинается заново.
- **Коды восстановления**: 10 одноразовых кодов, в базе только хэши. Заменяют при входе
  один шаг (код из письма или файл ключа), при сбросе пароля — код из письма.
- **Сессии** хранятся на сервере: в cookie только случайный токен (HttpOnly, SameSite=Lax),
  в базе — его хэш. При входе токен меняется, при выходе, сбросе пароля и блокировке
  сессии удаляются. Все формы защищены CSRF-токеном.
- **Роли** проверяются на сервере для каждой закрытой страницы; администратор не может
  разжаловать или заблокировать сам себя.
- **Сообщения**: Кузнечик — новый случайный ключ на каждое сообщение, RSA — ключ системы.
  Шифртекст вместе с автором, временем и алгоритмом подписывается ЭЦП автора.
- **Секреты сервера** лежат в `instance/` и не попадают в Git: мастер-ключ (создаётся сам,
  права 0600), ключ RSA. Ключи Кузнечика и копии закрытых ключей ЭЦП хранятся в базе
  зашифрованными мастер-ключом.

## Известные ограничения

- Защиты от перебора паролей на первом шаге входа нет (на шагах 2 и 3 — 5 попыток).
- Режим гаммирования без имитовставки: целостность сообщений обеспечивает ЭЦП.
- Защита RSA-расшифрования от атак по времени (RFC 8017, п. 7.2.2) не делалась.
- Расшифрование RSA-32768 — около 30 секунд на блок; сообщения ограничены 4000 байт.
- Запуск рассчитан на локальную демонстрацию: встроенный сервер Flask, база без пароля
  на localhost, cookie без флага Secure (нет HTTPS).
